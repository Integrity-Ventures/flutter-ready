(develop @ 75c8769). After 30m12s it died:

per-plugin error handling. The contract (architect notes, schemaVersion 1)

aborts the run**. Discovery is also sequential, one score fetch at a time,
which is why the run took so long.

1. **No per-plugin failure may abort the run.** Any exception while checking
   one plugin (fetch, gzip/tar decode, ELF parse, Gradle parse, pubspec
   parse) is caught and recorded in that plugin's `errors` with the
   package name, and the run continues. Make sure stream errors from the
   HTTP body and the gzip filter are caught, not only synchronous throws.
   Add an offline test with a corrupt `.tar.gz` archive: the plugin records
   an error and the others still assemble.
2. **Discovery concurrency:** fetch score tags with the same pool of 4 used
   for assembly, while keeping ranking order and the "stop at N plugins"
   rule. Keep the descriptive User-Agent.
3. **Progress on stderr** every 50 plugins, so a long run is visible.
