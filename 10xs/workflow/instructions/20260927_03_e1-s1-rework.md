## Objective

Make `discoverFlutterPlugins` return the top N real Flutter plugins, as
SPEC §3.1.1 intends.

## Why (review findings)

1. **Spec deviation.** `packages/readiness_check/lib/src/plugin_discovery.dart`
   applies `topN` to the raw ranked name list *before* filtering, so
   `topN: 100` yields far fewer than 100 plugins. SPEC §3.1.1 says "top N
   Flutter plugins". N counts plugins after the filter.
2. **The filter keeps non-plugins.** Measured on pub.dev 2026-09-27 (score
   endpoint tags):
   - `provider`: `sdk:flutter platform:android platform:ios …`, no `is:plugin`
   - `flutter_map`: `sdk:flutter platform:android platform:ios …`, no `is:plugin`
   - `url_launcher`: `… is:plugin …`
   - `shared_preferences`: `… is:plugin …`

   Pure-Dart Flutter packages carry every platform tag, so the current
   filter puts them on the board, where they would show as false reds (no
   Package.swift, no .so). The acting PM approved, for the owner on
   2026-09-27, also requiring `is:plugin`.

## Implementation Steps

1. `packages/readiness_check/lib/src/plugin_discovery.dart`:
   - `_isFlutterPlugin` also requires the tag `is:plugin`.
   - Walk the ranked list in order, fetch tags, keep the matches, and stop
     once `topN` plugins are collected (or when the list runs out). Keep
     `topN` defaulting to 100. Fix the doc comment to match.
2. `packages/readiness_check/test/plugin_discovery_test.dart`:
   - Add `is:plugin` to the url_launcher fixture tags and add a
     provider-style entry (sdk:flutter + platform:ios/android, no is:plugin).
     Assert the provider-style entry is dropped.
   - Replace "applies topN to the raw list before filtering" with a test
     showing that `topN` counts plugins after filtering, and that fetching
     stops once N are found.
3. `SPEC.md` §3.1.1: add the `is:plugin` requirement to the filter sentence
   with a dated note, e.g. "(added 2026-09-27, acting PM for the owner:
   pure-Dart packages such as provider and flutter_map carry the platform
   tags too; url_launcher and shared_preferences carry is:plugin)". The
   owner can revert it with one line.
