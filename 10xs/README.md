## Getting Started (5 steps)

### Step 1: Initialize your repo (~2 min)

```bash
git init
git add .
git commit -m "chore: bootstrap Project OS from 10xs.ai export"
```

This gives you a clean baseline to diff against as you evolve the project.

### Step 2: Configure your AI tool (~2 min)

Copy `10xs/CLAUDE.md` to your tool's config location:

| Tool | Setup |
|------|-------|
| Claude Code | `cp 10xs/CLAUDE.md CLAUDE.md` (project root) |
| Cursor | `cp 10xs/CLAUDE.md .cursorrules` |
| Windsurf | `cp 10xs/CLAUDE.md .windsurfrules` |
| GitHub Copilot | `mkdir -p .github && cp 10xs/CLAUDE.md .github/copilot-instructions.md` |
| Cline | `cp 10xs/CLAUDE.md .clinerules` |

**MCP Servers** (if `.mcp.json` was exported): `cp 10xs/.mcp.json .mcp.json`

### Step 3: Enrich CLAUDE.md (~5 min)

The exported `CLAUDE.md` contains governance rules and project constraints extracted from your PRD. Some fields may say "Stack: Not specified" — fill these in with your actual technology choices.

**Architect prompt to enrich:**
```
You are software architect. Read 10xs/CLAUDE.md, review the PRD and Blueprint,
then update CLAUDE.md with concrete stack choices, repo conventions, and any
project-specific rules the team should follow.
```

### Step 4: Triage the Decomposition (~30 min)

The Decomposition is a **skeleton, not a plan**. It gives you epics, stories, and microtask outlines — but each microtask needs a proper instruction file before a coding assistant can execute it.

**Architect prompt to triage:**
```
You are software architect. Read 10xs/architecture/generated/DECOMPOSITION.json
and the Blueprint. Identify the highest-priority epic, flag any issues, and
recommend which story to start with.
```

**Common issues to watch for:**
- Duplicate microtasks across stories
- Research-only tasks with no concrete deliverable
- Empty `targetFiles` or `implementationNotes` fields
- Microtasks that are too large (should be ≤5 implementation files)

### Step 5: Write the first real instruction (~30 min)

Pick a microtask from Step 4 and create its instruction file:

```bash
mkdir -p 10xs/workflow/instructions
```

**Architect prompt to write instruction:**
```
You are software architect. Read the doctrine in 10xs/doctrine/ (especially
TASK_WORKFLOW.md). Create a microtask instruction file for [chosen microtask]
in 10xs/workflow/instructions/ with implementation steps, success criteria,
and max 5 implementation files.
```

## Development Loop

```
Architect writes instruction
        ↓
Coding Assistant executes microtask
        ↓
Coding Assistant submits completion report
        ↓
PM / Architect reviews report
        ↓
Next microtask assigned
```

Each cycle produces a tested, validated increment. The governance doctrine
ensures consistent quality across sessions and team members.

## Starting a Session

**As Architect** (plan work, create microtasks, validate reports):
```
You are software architect. Read 10xs/CLAUDE.md, review current state,
and recommend the next task.
```

**As Coding Assistant** (implement microtasks, write tests):
```
You are coding assistant.
Your task: [path to microtask instruction file]
Strict adherence to coding standards. Provide completion report.
```

## Key Concepts

**Decomposition is a skeleton, not a plan.** The AI-generated decomposition
gives you structure — epics, stories, microtask outlines — but each microtask
needs a human-reviewed instruction file before execution. Think of it as a
table of contents, not a finished book.

**One instruction at a time.** Each coding session should focus on a single
microtask instruction file. The instruction defines scope (max 5 files),
success criteria, and expected evidence. This prevents scope creep and makes
progress measurable.

**Evidence-based quality.** Every microtask produces a completion report with
test results, screenshots (for UI work), and build verification. Reports that
claim success without evidence are rejected. Honest failure reports are more
valuable than false success claims.

## Re-Export

When the project evolves, re-run the export pipeline and use `MERGE_GUIDE.md`
for safe incremental updates that preserve your local files.
